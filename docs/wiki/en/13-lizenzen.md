# 13 · Licences

Summary. In detail with original quotes: `plan.md` §3.
**Not legal advice** — but checked against the licence text, not from memory.

## Short version

**Operation within the company is covered.** The line is not drawn at the number of users, but at
passing things on to the outside.

## The components

| Component | Licence | Assessment |
|---|---|---|
| **Microsoft VS Code** | proprietary, MS EULA | Internal deployment **explicitly allowed**, unlimited copies |
| **VSCodium** | MIT | free. Open VSX only |
| **IntelliJ IDEA Community** | Apache-2.0 | free for commercial use |
| **IntelliJ Ultimate** | proprietary | **Named-user licence per developer**, activation by the user |
| **opencode** | MIT | free |
| **Cursor** | proprietary | **check before adding** — see below |
| **Selkies** | MPL-2.0 | The streaming engine of the default image. **OTA modifies it** — see below |
| **libx264** | GPL-2.0+ | The encoder behind it. The actual obligation when passing on — see below |
| **KasmVNC** | GPL-2.0 | The older path, for Kasm images. Own operation free; when **passing on**, the GPL obligations apply |
| **Archivo, IBM Plex Mono** | SIL OFL 1.1 | The interface's fonts. They are in the repository and shipped |
| **Kasm workspace images** | MIT **only for the build recipes** | The finished image is not MIT — see below |
| **Kasm Workspaces server** | commercial EULA | **is replaced by OTA** |
| Docker, Traefik, PostgreSQL, XFCE | Apache-2.0 / MIT / PostgreSQL / GPL | free |

> **An image is a combined work.** The rows of this table describe individual components, not the
> result. A workspace image contains OTA configuration, Selkies, libx264, XFCE, hundreds of
> distribution packages and the installed applications — each with its own licence. **None of it
> is relicensed by OTA.** The breakdown into three levels is in
> [THIRD-PARTY-NOTICES.md](../../../THIRD-PARTY-NOTICES.md).

### Passing on the default base image — four obligations

`ota/base-desktop` **may** be passed on. Whoever does so has four things to take care of:

1. **Offer sources for the GPL parts** — libx264 and the rest of Debian. A reference to the
   distribution is not enough if the image was modified; the bill of materials names the versions.
2. **Include the changes to Selkies.** The MPL-2.0 applies **per file**: **five** files are changed,
   and exactly those must go along openly. They are in the repository as patches
   (`images/base-desktop/patches/`) and listed individually in
   [THIRD-PARTY-NOTICES.md](../../../THIRD-PARTY-NOTICES.md).
3. **Leave licence texts in the image.** They are where the packages put them.
4. **Ship a bill of materials** — `make sbom`, SPDX and CycloneDX.

**Finished workspaces with Microsoft VS Code or Google Chrome, on the other hand, may not** — the
same with VSCodium and Firefox may. The line runs at the application, not at the base image.

### The interface's fonts

Archivo and IBM Plex Mono are under `web/public/fonts/` and are shipped. The OFL explicitly allows
that as long as the fonts are not sold on their own and the licence goes along — it lies next to
each font.

**Until 2026-09-04 they were loaded from Google on every visit.** This sent every user's IP address
to Google LLC in the USA. That is not a licence question but one of data protection, and it was the
only data flow out of this installation. It no longer exists: the interface loads nothing **from any
foreign host** — it looks the same offline and behind a corporate proxy.

## Operating or passing on — the line that matters

Almost every question in this chapter has two answers, depending on which side of this line you
stand:

| | Own company | Passing on to the outside |
|---|---|---|
| What is meant | Own employees access an internally operated installation through the browser | Publishing an image, running an offering for third parties, delivering an installation |
| KasmVNC (GPL-2.0) | free, no obligations | Include licence text and notices, keep source code available |
| Kasm build recipes (MIT) | free | Keep the copyright notice |
| Microsoft VS Code | **explicitly allowed** | **not covered** |
| Distribution packages | free | respective obligations, in sum only manageable with a bill of materials |

**OTA is built for the left column** (`plan.md` §17.4b). Whoever wants to move into the right one
does not have a licence problem of the project, but a series of their own checks ahead — starting
with VS Code.

### The bill of materials

For the right column it is available at the push of a button:

```bash
make sbom                        # all OTA images
scripts/sbom.sh ota/api:dev      # or individual ones
```

Per image two files are created under `sbom/`, **SPDX** and **CycloneDX** — the two formats
recipients usually ask for. It is generated by `syft`, which runs as a container; nothing has to be
installed, and the Docker socket goes in read-only.

Such a list cannot be maintained by hand: a workspace image brings well over a thousand packages,
and the day after the next `apt upgrade` the list would be wrong. A wrong bill of materials is worse
than none, because someone believes it.

The files do **not** belong in the repository. They apply to exactly the state they come from and
go out of date with the next build; whoever passes an image on generates them fresh and adds them.

## Microsoft VS Code

The EULA says in §1a, literally:

> "You may use **any number of copies** of the software to develop and test your applications,
> **including deployment within your internal corporate network**."

No user limit, no fee, internal network operation explicitly named.

§5 prohibits:

> "share, publish, rent or lease the software, or **provide the software as a stand-alone offering
> for others to use**."

| Plan | Permitted |
|---|---|
| Own employees in the company network | **Yes** |
| Golden image in an **internal** registry | **Yes** |
| Any number of users and sessions | **Yes** |
| Image in a **public** registry | **No** |
| Selling or hosting OTA for customers | **No** |

**As soon as real third parties are to get access** — customers, partner companies — they need a
golden image with **VSCodium** instead of the Microsoft build.

### Marketplace

According to Microsoft's terms of use, the official marketplace may **only be accessed by
MS-branded products**. VS Code may, VSCodium and Cursor may not — they use Open VSX or their own
registries.

**Two things follow from that:**
1. The desktop variant of VS Code in the container is the legally clean way to the marketplace.
   `code-server` and `openvscode-server` would have to switch to Open VSX.
2. VSCodium and Cursor must **not** be bent to the MS marketplace via configuration. That is
   technically possible and not permitted under the licence.

**OTA checks this after every build.** As soon as an image is in the store, the build reads the
`product.json` of every editor found and writes to the log where it fetches its extensions from. If
a non-Microsoft editor points to `marketplace.visualstudio.com`, a warning appears there. The build
does not fail because of it — the image is built and usable; the decision to distribute it like
that belongs to a human.

In the current workspace image it looks like this:

```
Erweiterungs-Marktplatz der gefundenen Editoren:
  VS Code (Microsoft): https://marketplace.visualstudio.com/_apis/public/gallery
  VSCodium: https://open-vsx.org/vscode/gallery
```

So correct. A troubleshooting note: a simple `grep` for `marketplace.visualstudio.com` in
VSCodium's `product.json` **finds a hit** and is still no finding — the name is there under
`extensionAllowedBadgeProviders`, that is, in the list of hosts from which badges in a README may be
loaded. Only `extensionsGallery.serviceUrl` is decisive.

### Telemetry

VS Code sends telemetry to Microsoft (EULA §2). In business use that is a GDPR topic.
Recommendation: preset `"telemetry.telemetryLevel": "off"` in the skeleton profile.

## KasmVNC — GPL-2.0

- **Operation unrestricted and free.** The GPL knows no user limits and no fees
- Obligations only arise when **passing on**. Letting employees access an internally operated
  instance through the browser is not passing on. GPLv2 also has no network clause
- **OTA itself does not have to be GPL** — it only talks to KasmVNC via HTTPS and WebSocket, links
  no GPL code and embeds none
- Whoever **passes on** KasmVNC — and that is anyone who publishes an image with it — must keep the
  licence text and notices and keep the corresponding source code available. That does **not make
  the whole image GPL**; it means the GPL part stays a GPL part
- Besides the GPL, KasmVNC keeps its **own list of third-party notices**, and Kasm itself notes
  that it is not necessarily complete. Whoever distributes an image containing KasmVNC therefore
  includes the licence and notice files of the respective version instead of relying on
  "KasmVNC = GPL-2.0"

### May KasmVNC go into our own image?

Yes — checked on 2026-09-01, when the own base image was created
([chapter 19](19-eigenes-basisimage.md)).

It was not looked up in a blog post but in the file that lies in the built image itself:
`/usr/share/doc/kasmvncserver/copyright` says `License: GPL-2+`, and the copyright line lists Kasm
Technologies next to AT&T, RealVNC, TightVNC, Sun and the TigerVNC team — KasmVNC is a TigerVNC
descendant and inherits its licence.

The package is taken over **unchanged** from the official release, not patched, not linked, and
started as a program of its own. In the image it lies next to other software without infecting it —
the case the GPL calls *mere aggregation*.

**It is even cleaner than the previous way.** Until now every workspace derived from a `kasmweb/*`
image, and its finished image is precisely not MIT (see the next section) — what is in it under
which conditions has to be found out package by package. Ubuntu + XFCE + the official KasmVNC
package, by contrast, consists of individually traceable components.

When passing on, this means: leave the licence files in the image (they are under
`/usr/share/doc/kasmvncserver/` anyway), refer to
`github.com/kasmtech/KasmVNC/releases/tag/v<version>` — the version is in the Dockerfile as
`KASMVNC_VERSION` — and include the generated bill of materials (`make sbom`).

**What does not work:** Kasm's *Workspaces* platform is proprietary — agent, manager, API, the
product's web interface. Nothing of it goes into an OTA image. And the name belongs to Kasm: our
image is called `ota/base-xfce`, not "Kasm" anything.

## Kasm images — MIT

The build recipes are under MIT. The disclaimer of the licence file is important:

> "This license applies **only to the source code that is directly maintained in this git
> repository** … to include other projects owned and/or maintained by Kasm Technologies."

MIT therefore applies to the **Dockerfiles**, not to the content of the finished images. Every
contained package keeps its own licence.

Consistently, GitHub does not list the Kasm image repositories as "MIT" but as *Other* — checked on
2026-08-28 via the GitHub licence API.

**Trademarks**: "Kasm" and "Kasm Workspaces" are protected; MIT grants no trademark rights. OTA may
not use them in the product name, logo or domains. The MIT copyright notice must be kept in derived
Dockerfiles.

## Cursor — clarify before adding

Cursor is **deactivated** in the app catalog. Two points are open:

1. Does Cursor's EULA allow operation in a centrally provided multi-user environment, and do the
   users each need their own licence? With Pro subscriptions, named-user should be assumed.
2. Cursor is a VS Code fork and therefore **not an MS-branded product** — the MS marketplace must
   not be accessed from it.

OTA cannot take this check off your hands.

## Imported registry images

That a registry lists an image is **no statement about its licence**. Contained applications can be
proprietary or require user licences. Check before rolling out.
→ [chapter 9](09-kasm-images-und-registries.md)

## Rule for every new golden image

Check and document an application's licence before adding it. Rule of thumb: packages from the
Debian and Ubuntu sources are uncritical; vendor binary packages (Chrome, JetBrains Ultimate,
Microsoft products, Cursor) need an individual look.
