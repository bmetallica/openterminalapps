# 27 · OTA Git (Forgejo) ✅

A Git platform that belongs to OTA: [Forgejo](https://forgejo.org) under its own subdomain. You turn
it on and off under **Settings → Git**. When it is on,

- people sign in **with the same credentials as in OTA**, through Keycloak, with the same second
  step;
- only the **entitled groups** get in, plus always the administrators;
- OTA **creates the accounts itself**, even before someone signs in for the first time. Whoever loses
  their entitlement is **locked, never deleted**. **OTA admins are admins in Forgejo too**;
- every entitled **workspace gets Git preconfigured**, root workspaces included. Other Git servers
  remain usable alongside;
- a tile **Git** appears in the application catalog. It starts the sign-in through Keycloak right
  away; with the session from OTA you are in without an intermediate step.

Turning it off only stops it. Repositories, accounts and database stay, and turning it on again
continues where it left off.

## Turning it on

1. Enter the **subdomain**, e.g. `git.company.com`.
2. Check the **OTA address** as browsers see it, e.g. `https://ota.company.com`. Forgejo finds the
   sign-in (Keycloak) through it. The default is the address you are working under right now.
3. **Who may**: choose the groups. Without a group only administrators get in.
4. Flip the switch. The first time, OTA pulls the Forgejo image
   (`codeberg.org/forgejo/forgejo:15.0.10`, set in `OTA_GIT_IMAGE`). After that it takes about
   15 seconds.

What happens:

- The database `forgejo` with its own user is created in the existing Postgres.
- The agent issues a certificate for the subdomain, from the OTA CA.
- A client is created in Keycloak, with the usual group access.
- The agent starts the container `ota-git` with the volume `ota_git_daten`.
- The agent sets up the emergency access `ota-admin` and the sign-in source.
- Finally the accounts are synced.

The two secrets for this, `OTA_GIT_DB_PW` and `OTA_GIT_ADMIN_PW`, are generated by `make update` in
`deploy/.env`. The container is created by the **agent**, not by Compose, otherwise it could not be
switched from the interface.

## Ways in and ports

```
Browser ──https──▶ Reverse proxy ──https──▶ OTA host :8443 (Traefik, the same entrance as OTA)
  git.company.com                                 │  Host: git.company.com
                                                  ▼
                                            ota-git :3000 (http, internal only)
```

| Port | Where | What for |
|---|---|---|
| 8443 (`OTA_HTTPS_PORT`) | host, as before | HTTPS for OTA **and** the subdomain. Traefik separates by name |
| 3000 | internal only, `ota-git` | Forgejo behind Traefik |
| 443 | only in the session networks (Traefik `git-intern`) | HTTPS from the workspaces |
| 2222 | only in the session networks (Traefik `git-ssh`) | Git over SSH from the workspaces |

**Forgejo itself listens on 3000, and this port is never published.** For the subdomain the reverse
proxy targets **the same port as for OTA**. No port and no firewall rule is added. Under the
subdomain everything belongs to Forgejo, including `/api`: its rule takes precedence
(`priority 1000`) over OTA's path rules.

**At the reverse proxy**, each subdomain needs the same as OTA, plus the name in the TLS handshake to
OTA (SNI). The example is in [chapter 24](24-hinter-nat.md#and-the-ota-git-subdomain). Behind the
proxy, Traefik trusts the forwarded headers only from `OTA_TRUSTED_PROXIES` as before, and Forgejo
only trusts Traefik.

**DNS** is only needed by the browsers: an entry for the subdomain pointing to the reverse proxy,
without a proxy to the host. The settings show whether the OTA host resolves the name. Workspaces
need no entry, see below.

**Forgejo to Keycloak** needs no DNS. Forgejo asks Keycloak server-side under the "OTA address".
For that, Forgejo and Traefik share a small network of their own, `ota_git_anmeldung`, in which
Traefik carries OTA's name. Only Forgejo resolves it that way. There Traefik forwards on 443 only
`/auth` to Keycloak, and only from this network; the workspaces still see only Git on 443. If OTA's
certificate does not cover the name, the agent adds it to the subdomain's certificate. This applies
to addresses without a port or with 8443; on other ports it stays with the host's DNS. A newly
created Traefik is attached again by the agent at the next sync, after 15 minutes at the latest.

## In the workspace

If Git is on, the person is entitled and the template does not turn off **Preconfigure Git**
(default: on), OTA sets up as root on every start and every resume:

- **`/etc/hosts`**: the subdomain points to Traefik in the workspace's own session network. That
  needs neither company DNS nor a way through the proxy, and works even with the network profile
  "no company network".
- **`/etc/ota-git/`**: a token, a credential helper, OTA's CA, name and email.
- **`/etc/gitconfig`** includes it via `[include]`, so at system level, the one with the lowest
  precedence:
  - The helper and the CA apply **only to `https://<subdomain>`**. Another server gets neither token
    nor CA.
  - `user.name` and `user.email` come from OTA. What the person sets in `~/.gitconfig` wins.
  - The home is not touched. Own credentials, SSH keys and helpers for GitHub or a company server
    stay as they are.

With that, `git clone https://git.company.com/…`, `push` and VS Code work without a password prompt.

**The token:**

- It applies **per workspace** and may only read and write repositories and see its own name.
- **When the workspace ends, OTA revokes it.** That applies to ending, stopping and the reaper, plus
  every 15 minutes for anything that slipped past.
- A root workspace gets a new one when resuming.
- It lives in `/etc/ota-git`, not in the home, and so does not end up in the profile backup.

**SSH**: the person enters their key in Forgejo themselves (Settings → SSH keys). Then
`git clone ssh://git@git.company.com:2222/…` works, **only from workspaces**. Forgejo also shows this
address to browsers from outside, where it does not work. From outside, HTTPS applies.

**git in the image**: since 2026-10-21 the base image keeps `git` (before, it was removed again after
the build). Older images: rebuild the base image (`scripts/build-desktop-image.sh --pruefen`) and the
workspace images afterwards, or install `git` in the recipe or in the root workspace. The setup takes
effect as soon as git is there.

## Accounts

| Event in OTA | In Forgejo |
|---|---|
| Member of an entitled group, or admin | create or unlock the account |
| Admin | Forgejo admin; without the role, not any more |
| removed from the group, disabled, locked | sign-in locked (`prohibit_login`) |
| deleted | locked; repositories stay |
| renamed in the directory, domain account linked ([chapter 08](08-nutzer-und-gruppen.md)) | renamed; an account that already carries the name is renamed aside and locked |

Syncing happens at every sign-in through Keycloak, after every change in administration, after every
directory sync, every 15 minutes and with **Sync accounts now**. An account OTA created is **linked,
not duplicated** at the first sign-in in the browser.

Everyone may create repositories. New repositories are private.

**Emergency access**: `ota-admin` with the password from `OTA_GIT_ADMIN_PW`, via Forgejo's sign-in
form. OTA maintains the accounts through it. The password is set from `.env` every time it is turned
on.

## Changing settings

- **Another subdomain:**
  - New certificate and new redirect address in Keycloak.
  - The container is replaced, the data stays.
  - Workspaces get the new address at the next start or resume.
  - Clones with the old address are switched with
    `git remote set-url origin https://<new>/…`.
- **Other groups:** take effect immediately for tile and Keycloak. Accounts are synced right away.
- **Turning off:** stop the container, tile and Keycloak client gone. Tokens no longer work.

## Backup and restore

Once Git is set up, the backup run backs up OTA Git together with the database, under
`/srv/ota/backups/git/<time>/`:

- `forgejo.sql.zst` contains the database.
- `daten.tar.zst` contains `/data` with repositories, attachments and keys.

That also works while Git is off.

Restoring is done by hand:

```bash
# 1. In the interface: Settings → Git → off
D=/srv/ota/backups/git/<time>
zstd -dc $D/forgejo.sql.zst | docker exec -i ota-db psql -q -U ota -d forgejo
zstd -dc $D/daten.tar.zst | docker run --rm -i -v ota_git_daten:/data \
  --entrypoint tar codeberg.org/forgejo/forgejo:15.0.10 x -C /
# 2. Settings → Git → on
```

## Removing

Turning it off deletes nothing. Whoever wants to get rid of OTA Git entirely removes by hand after
turning it off:

```bash
docker rm ota-git && docker volume rm ota_git_daten
docker exec ota-db psql -U ota -c 'DROP DATABASE forgejo' -c 'DROP ROLE forgejo'
```

## When something does not work

| What | Cause |
|---|---|
| After signing in at Keycloak, back on Forgejo's sign-in page | The sign-in source is not up to date. Turn it off and on once; OTA restarts Forgejo after every change of the source (the running server only reads it at start) |
| "No access to this application" | Not in an entitled group, or disabled |
| Browser: certificate does not match | Without a proxy: the browser must trust the OTA CA. With a proxy: check the certificate at the proxy |
| OTA appears under the subdomain, or Keycloak reports `Invalid parameter: redirect_uri` | The proxy does not send the name along (`Host`, SNI). Caddy on OPNsense: in the handler protocol `https://` and an "upstream" header `Host` = `{host}`. Nginx Proxy Manager: scheme `https`, the `Host` is right there by itself |
| After sign-in a 404 on `/sw.js` | A browser that once saw OTA under the subdomain keeps its service worker. Clear the subdomain's site data once (F12 → Application → Clear site data) |
| Turning it on reports `Anmeldequelle: … lookup <name> … no such host` | State before 2026-10-22: Forgejo looked up Keycloak via DNS. Update with `git pull && sudo make update` and turn it on once. On a port other than 443 or 8443: the OTA host must resolve the name |
| Keycloak asks for the password again on the way from OTA to Git | The "OTA address" is not the one under which the browser opens OTA |
| In the workspace git asks for user and password | `git` was missing at start, the template turned it off, or the person is not entitled. Check: `git config --show-origin --get-regexp credential` |
| Forgejo does not start | `docker logs ota-git`. Often the database: is `OTA_GIT_DB_PW` set in `deploy/.env`? |

Test suite: `scripts/test-git.sh` (52 checks, also behind an nginx as reverse proxy).
